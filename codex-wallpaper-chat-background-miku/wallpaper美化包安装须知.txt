# wallpaper美化包安装须知

项目：**codex-wallpaper-chat background-miku**  
适用：Windows 10/11 上的 Codex 桌面应用。本文是 Markdown 格式，以 UTF-8 `.txt` 保存。

## 1. 这个包做什么

- 将动态 MP4 覆盖整个 Codex 内容窗口，包含侧栏、聊天区、顶部和输入区。
- 使用暗色外观、磨砂面板和边缘羽化，视频不拦截鼠标操作。
- 一个视频循环播放；多个 MP4 按文件名排序依次播放；默认静音，窗口隐藏时暂停。
- 登录 Windows 后自动启动隐藏的监视器。以后从原来的 Codex 桌面、任务栏、开始菜单入口启动即可，**不需要额外的壁纸快捷方式**。
- 普通 Codex 没有壁纸所需启动参数时，监视器会在新启动阶段自动中转重开一次，然后挂载壁纸。已经运行的会话会作为基线保留。

这是本地桌面定制工具，不是能修改宿主背景的官方 Codex 插件。无需修改 WindowsApps 安装包；Codex 更新后可能需要修正页面选择器。

开源源码包与个人本地包不同：源码包不包含个人视频、登录配置或运行日志。源码包使用者应先自行准备视频，再运行安装器。本地打包素材的权利不随代码的 MIT 许可证转移。

## 3. 安装前准备

1. 已安装 Windows 版 Codex。
2. Node.js **22 或更新版本**。优先使用 PATH 中的 `node.exe`；也会寻找当前用户 Codex 自带的 Node 运行时。不需要 npm install。
3. 将完整文件夹解压到稳定路径，保留所有脚本与 `wallpapers` 子目录的相对位置，不要只复制单个 CMD。
4. 确认 `wallpapers` 中至少有一个有效 MP4。

## 4. 一次性安装与日常启动

双击本文件夹的 `install.cmd`。也可以在该文件夹打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

安装器验证 Node、设置和素材，注册隐藏的登录启动项，清理旧版工具自己创建的多余桌面/开始菜单壁纸图标，然后启用两个后台程序。**默认保留原来的 Codex 图标，不再新建第二个桌面图标。**

首次启用时，当前已有 Codex 会话不会自动关闭。保存输入后完整退出 Codex，包括托盘后台，再从原入口正常打开一次。之后由后台监视器自动联动。

如果暂时不能重启，使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -NoStart
```

这只保存启动配置，不重启 Codex，也不更换当前后台进程。之后在允许启用时运行普通安装命令；或者下次登录 Windows 后由启动项启用后台程序。**“配置已保存”不等于当前窗口已经加载新版壁纸。**

后台启动项位于当前用户的 Windows Startup 文件夹，名称为 `Codex Wallpaper Watcher.lnk`，目标是本包的 `watcher-start.ps1`。该启动项不是桌面图标。

工具使用独立的本地应用配置目录，第一次可能需要重新登录。移动文件夹后应重新安装，以修正启动项路径。

## 5. 本次最终画面参数

`settings.json`：

```json

  "opacity": 0.68,
  "veil": 0.16,
  "appearance": "dark",
  "starHighlights": true,
  "highlightOpacity": 0.98
```

| 星光叠层不透明度 | 0.98（98%） | 眼睛黄色五角星、右上/左下十字闪光 |
| 背景铺放 | cover / center | 保持比例铺满，窄窗口可能裁切两边 |
| 暗色边缘 RGB | 24,25,29 | 固定在 renderer.js |
| 暗色面板 RGB | 28,29,34 | 固定在 renderer.js |
| 右上卡片 | 76% + blur 20px | 饱和度 115% |
| 输入框 | 79% + blur 18px | 饱和度 110% |
| 顶部玻璃层 | 25% + blur 12px | 与原应用结构适配 |
| 左侧羽化 | 74%→54%→22%→透明 | 250 / 345 / 500 CSS px 节点 |
| 底部羽化 | 96%→66%→透明 | 38 / 180 CSS px 节点 |
| 顶部羽化 | 55%→透明 | 95 CSS px |
| 右侧羽化 | 25%→透明 | 65 CSS px |

| 星光分析画布 | 640×360 | 只计算透明度遮罩 |
| 星光最终叠层 | 随窗口/DPR，最高 3840×2160 | 颜色取当前高分辨率视频原帧 |

前五个参数可在 JSON 中修改，其余视觉常量位于 `renderer.js`。修改后停止并重新启动后台程序使其重新读取配置。页面已为暗色时沿用当前外观；需要更改时尝试通过 Codex 的原生设置接口保存。

**1.0.1 兼容修复：** Codex 26.1021 移除了旧的 `set-setting` 接口。新版先检查页面是否已为暗色，避免重复调用旧接口；外观设置接口失败也不会阻止动态壁纸加载，具体错误写入 `watcher-error.log`。若当前 Codex 仍为明亮模式，请在 Codex 的外观设置中选择暗色，壁纸后台保留原透明度等配置继续工作。

**启动中转修复：** Electron 在启动期间可能继续创建渲染或工具子进程。1.0.1 会核对这些新进程与已捕获启动进程的父子关系、创建时间及可执行路径；不再因本次启动的正常子进程而取消中转。其他主进程、无关进程和被复用的 PID 仍会受到保护。Windows 登录仅启动壁纸后台，打开原 Codex 图标后才加载壁纸。

**1.0.2 重启识别修复：** 监控改为比较主进程的 PID、精确创建时间和可执行路径。旧主进程已退出而新主进程出现时，即使轮询没有看到整个进程列表清空，也会识别为新会话。旧 crashpad 等子进程短暂残留时先等待其退出，不结束这些旧进程，也不永久锁住新会话。仍保留十秒启动时限和对存活主进程的保护。更新文件后，在普通 Windows 会话运行一次 `install.cmd`，使常驻后台重新载入新版代码；只重开 Codex 不会更新已经运行的监控脚本。

## 6. wallpapers 文件夹的视频要求

实际文件夹名是 **`wallpapers`（复数）**。

- 只扫描该文件夹的顶层 `*.mp4`，不递归扫描子文件夹。
- 推荐 MP4 容器、H.264 编码、`yuv420p` 像素格式，30fps 或 60fps。HEVC 是否流畅取决于本机解码支持。
- 推荐 16:9、1080p 或 4K；短循环约 3～15 秒更便于控制体积。超高分辨率不自动带来更多源细节。
- 单个 MP4 不超过 **64 MiB（67,108,864 字节）**；全部 MP4 合计不超过 **128 MiB（134,217,728 字节）**。
- 多个视频用 `01-name.mp4`、`02-name.mp4` 等清楚命名，按文件名排序播放。
- 原声可保留，但壁纸播放器默认静音。
- 循环首尾应接近；补帧版已补入末帧到首帧之间的中间帧，保持原时长。
- Miku 专用星光增强依赖文件名 `miku.mp4`，并且只适合本包的原始 Miku 构图。给别的视频改成这个名字，并不会自动识别它的眼睛或星星。
- 12K 母版大于自动播放体积限制，放在 `masters` 中保存，**不要复制进 wallpapers**。日常使用 4K60 播放版。

本次原素材为 1280×720、30fps、3.90 秒、117 帧。动画超分后保留原构图，再用视频 AI 补入 117 张中间帧，得到 **234 帧、60fps、3.90 秒**。4K60 为 3840×2160；12K60 为 11520×6480。两个版本均完整解码验证，无解码错误。12K 是 AI 超分结果，不是原生 12K 拍摄素材。

图片生成功能制作的样张单独保留在 `previews`，没有把它的重绘差异强行插入最终动画。整段连续补帧使用 RIFE。

## 8. 暂停、重载、卸载

```powershell
.\pause.ps1                     # 暂停视频
```

## 9. 日志、状态和故障

后台文件位于 `%LOCALAPPDATA%\CodexChatWallpaper`，不在开源仓库和分发源码包中：

- `follow-codex.log`：检测、接管、跳过原因。
- `monitor-error.log`：监视器异常。
- `watcher.log`、`watcher-error.log`：挂载及视频状态。
- `monitor.json`、`watcher.json`：自有进程身份记录。
- `profile`：专用本机应用配置。不要上传这个目录。

常见情况：

1. 找不到视频：确认是 `wallpapers/*.mp4` 顶层文件，不是放在 masters 或嵌套文件夹。
2. 提示 64/128 MiB 限制：使用较小的日常播放版，不要把 12K 母版加入播放列表。
3. 当前窗口没有马上变：安装保留了既有会话，或只用了 -NoStart；需在允许时完成启用与完整退出。
4. 提示无法结束旧后台进程：在普通 Windows 会话运行 install.cmd；仍被系统拒绝时，注销后重新登录即可清除旧会话进程。不要反复强杀无关程序。
5. 新视频卡顿：优先 1080p/4K，降低解码负担。补帧增加帧数，不会修复硬件解码能力不足导致的丢帧。
6. 换目录后失效：重新执行安装器更新 Startup 路径。
